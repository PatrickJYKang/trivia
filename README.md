# Trivia

A static, responsive trivia game collection.

Serve `dist` with any static HTTP server. No build step or API key is required.

## City Guess

Standard mode has 100 curated, shuffled cities; no repeats until the deck is exhausted. “Too easy?” opens `?mode=hard`, titled City Guess (hard), with 1,000 cities across 171 countries. Hard mode includes all 100 standard cities, reserves up to three major cities per country, then fills the remaining places by population. Additional cities have at least 100,000 residents and city feature codes (excluding districts and abandoned places). The selection is deterministic and does not depend on source-file order. It uses the same clue, search and scoring rules. Switching modes starts a fresh session, and the hard-mode URL can be bookmarked. Hard-mode map crops adjust to population and latitude. Wrong guesses accumulate with great-circle distance and an initial bearing arrow from the guessed city to the answer. This history stays hidden until three actual wrong guesses, when all prior misses become visible; skipping clues does not unlock it early. Each round starts with major roads only, then an unlabeled OSM map, then satellite imagery. Choose a city from a searchable GeoNames database of 34,152 places. Results include region and country, support keyboard selection, accents and alternate names, and are matched by stable GeoNames ID. A wrong guess or a reveal advances the clue. Correct answers earn 3, 2, or 1 points. After a miss on satellite, keep guessing for zero points until correct or choosing Give up. Reviewing previous clues never restores points. Score lasts for the current page session.

Add cities and accepted aliases in `dist/cities.js`. Coordinates are longitude, latitude. Maps use a fixed, north-up view with no panning to other cities. Answers are client-side: this is a casual game, not a secure competition.

## Map sources

- Roads and unlabeled map: OpenStreetMap data via CARTO, with local CARTO Voyager style. https://carto.com/basemaps/
- Satellite/aerial imagery: Esri World Imagery public tiles. https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9
- MapLibre GL JS 5.6.2 is bundled locally, with its license in `dist/vendor/`.

Attribution stays visible below the map. Tile services require an internet connection and retain their provider terms and usage limits; no imagery is bulk downloaded or cached offline. Check provider terms before commercializing or scaling traffic.

Optional browser WebMCP tools use the same game actions and are feature-detected. Native WebMCP validation was unavailable in the local test browser.

## City search data

`dist/city-database.json` is a compact, population-sorted extract of GeoNames cities15000 and admin1CodesASCII, retrieved 2026-10-01. Includes cities, capitals and other populated places from that dataset; the standard mystery-city deck remains curated; hard mode builds a much larger deck from the database. Data © GeoNames contributors, CC BY 4.0 (https://creativecommons.org/licenses/by/4.0/). Source: https://download.geonames.org/export/dump/. Rows contain GeoNames ID, name, country code, administrative region, population, alternate names, latitude, longitude and GeoNames feature code. Transformation: selected fields, joined regions, deduplicated aliases, sorted population.

To refresh, download `cities15000.zip` and `admin1CodesASCII.txt` from GeoNames, then run `python3 scripts/build-city-database.py /path/to/cities15000.zip /path/to/admin1CodesASCII.txt`. Run `node --test tests/city-search.test.mjs` to check aliases and playable-city identity mappings.

## Heritage Guess

Open `heritage.html` (or choose **Heritage Guess** in the game navigation). Easy mode includes 100 curated UNESCO World Heritage properties; `heritage.html?mode=hard` includes all 1,272 properties with usable coordinates in the October 2, 2026 UNESCO DataHub snapshot. The source contains 1,273 entries, including 2026 inscriptions. One property, *Funerary and memory sites of the First World War (Western Front)*, has neither a reference coordinate nor component coordinates in that export and is explicitly recorded in `omitted` rather than assigned a guessed location.

The satellite view stays fixed. Four guesses earn 4, 3, 2, or 1 points. The first miss reveals the continent, the second reveals the country (all listed countries for a transboundary property), and the third reveals the UNESCO inscription criteria with short explanations. After the fourth miss, unlimited guesses earn zero points. Give up ends the round. Rounds are shuffled without repetition until the pool is exhausted. Easy/hard links start a fresh score session. The search covers the full mapped database in either mode, with official names in up to six languages, component names, and curated familiar aliases. Answers match the stable UNESCO property ID. Every wrong guess immediately adds its direction and distance to a persistent list below the form. History resets on the next round. The completed round links to that property's UNESCO page.

Ruins, destroyed or altered sites, cultural landscapes, natural sites and mixed properties are intentionally retained. A serial or transboundary property is one answer, represented by its listed reference point or its first georeferenced component when the main point is missing. Individual component names in search resolve to that parent property. Maps show present-day provider imagery, not historical reconstructions; capture dates vary. UNESCO reference points can be approximate. Zoom is estimated from property area per component, with focused crops for selected easy sites; it is not a property boundary. Remote imagery quality varies with Esri coverage.

### Heritage data and license

Source: [UNESCO DataHub — World Heritage List](https://data.unesco.org/explore/dataset/whc001/), retrieved 2026-10-02. The dataset metadata specifies **CC BY-SA 4.0**, attribution UNESCO. `dist/heritage-database.json` and its derived data are distributed under that license: https://creativecommons.org/licenses/by-sa/4.0/. Transformations: selected factual fields, stripped HTML markup from names, combined country names, multilingual/component aliases, curated easy selection, coordinate fallbacks, crop overrides, calculated zoom, and one omitted unlocated entry. UNESCO logos and site photography are not redistributed. This is an independent game, not affiliated with UNESCO.

Refresh the source with the JSON export at `https://data.unesco.org/api/explore/v2.1/catalog/datasets/whc001/exports/json`, then run `python3 scripts/build-heritage-database.py /path/to/export.json`. Review the new count, omissions and crop overrides before publishing. `node --test tests/*.test.mjs` validates both games' pools, searches, coordinate ranges and heritage scoring transitions. The heritage page also offers feature-detected WebMCP tools for search, guessing, revealing, and advancing, using the same UI actions.

### Geographic hints

`dist/guess-history.js` calculates haversine great-circle distances in km and initial bearings measured clockwise from north, from the guess to the answer. Distances use the same representative coordinates as each answer's map crop; these are point-to-point distances, not boundary or travel distances. City search retains GeoNames coordinates for every selectable answer. Very close but distinct locations display `<1 km`; identical coordinates have no directional arrow. Exact antipodes also have no unique bearing.

UNESCO criteria are read from the official export's `criteria_txt`. When empty (17 entries in this snapshot), the generator extracts explicit criterion labels from UNESCO's description/justification. Short criterion summaries are based on https://whc.unesco.org/en/criteria/. Continent hints refer to the pictured location, using Natural Earth country geometries (public domain) with geographic overrides for transcontinental countries, overseas territories and Polynesia/Hawaii. Offshore coordinates use nearest mapped land. Two offshore properties (Heard and McDonald Islands; French Austral Lands and Seas) use 'Subantarctic islands' instead of assigning them an artificial continent. These are conventional geographic groupings, not UNESCO's administrative regions.

To regenerate clue metadata, download `ne_110m_admin_0_countries.geojson` from https://github.com/nvkelso/natural-earth-vector/tree/master/geojson and run `python3 scripts/build-heritage-clues.py /path/to/unesco-export.json /path/to/countries.geojson`, then rebuild the heritage database. Review continent assignments when adding entries; the lookup is saved in `scripts/heritage-clues.json`. This derived lookup retains the UNESCO data license, CC BY-SA 4.0.

## City Bingo demo

Open `bingo.html`, the third game in the navigation. Five fixed 4×4 cards cycle in order: World tour, European circuit, Across Asia, Across the Atlantic, and On the compass. Each has a fixed sequence of 42 cities. URLs `bingo.html?card=1` through `?card=5` open a particular demo; Next card wraps from five to one. Restart replays the same sequence. There is no daily schedule, timer, live data fetch from a third party, or automatic refresh to maintain. Refresh starts the selected card over.

Place the displayed city in one matching empty category. Correct placements consume the city; incorrect placements discard it and skip the next city as a penalty. Skip consumes only the current city. One wildcard per card fills all matching empty squares with the current city (even zero matches consumes the wildcard and city). Complete rows, columns and diagonals are highlighted, and a full 16-square card is the main goal. Play ends on a full card or when all cities are exhausted. Results show filled squares, lines and mistakes. Routine move messages are omitted; the city, squares and counters update directly. Category details and hover titles define all thresholds.

The category mix uses country, continent, capital status, latitude/longitude, city-name prefixes and population bands. GeoNames snapshot populations are city-record estimates, not metropolitan populations; they may reflect different census years. Capital status follows the PPLC feature code (Delhi and New Delhi remain separate records). Continents use GeoNames countryInfo, with Russia split at 60°E for these demo selections. Country categories use the recorded country code. English/displayed names determine initial-letter categories. All data derives from GeoNames under CC BY 4.0; no player data, branding or assets from the football reference are copied.

`dist/bingo-data.json` contains all five fixed decks and their 179 distinct city records. `dist/bingo-model.js` defines category predicates, card templates and game transitions. `scripts/build-bingo-demo.mjs /path/to/countryInfo.txt` can regenerate the demo from the existing city database and curated city selections. It uses seeded shuffles and bipartite matching to guarantee a full solution for every card without a wildcard; runtime never regenerates the cards. Run `node --test tests/*.test.mjs` for solvability, penalties, skips, wildcard, exhaustion and regional data checks. Feature-detected WebMCP tools expose the same read/place/skip/wildcard/next actions.

## City Compass

Open `compass.html`, the fourth game in the navigation. Guess the mystery city at the centre using five arrows toward named cities. Answers use the top 200 cities in the editorial familiarity ranking, shuffled without repeats until exhausted. Clues are freshly generated each round from the full 1,000-city worldwide pool, retaining the broader range of clue difficulty. Every round guarantees one or two clues ranked 1–100 and one or two ranked 500–1,000; the remaining clues come from ranks 101–499. Difficulty uses an editorial familiarity ranking in `dist/compass-notability.js`: 100 curated international names (including Paris, Rome, Venice, Kyoto and Moscow), followed by curated regional names and national capitals. Population only orders cities within the remaining groups; this is a game difficulty guide, not an objective fame index. Independently, every round guarantees one or two close clues and one or two faraway clues, with the remainder at intermediate distances. Close and far mean the nearest and farthest fifths of eligible cities from the answer, so these bands adapt to remote locations too. Candidates are 350–18,500 km away with a defined bearing. The four counts are drawn separately and a matching step satisfies both sets of quotas together: easy or hard clues can be close, intermediate or far. Country and direction variety are optimized within those constraints. There is no daily schedule or fixed set of puzzles.

Arrows show straight-line directions **from the mystery city to each reference city** on a north-up Mercator world map. Longitude differences are not wrapped across the map edge: an eastern city stays to the right, and a northern city stays above, even for distant clues. These are map directions, not initial great-circle travel bearings; this avoids routes that initially head over a pole or around the date line. Great-circle distances still determine the independent close/far groups. Their equal lengths do not indicate distance. Thin connecting lines keep labels readable without changing the blue arrows' bearings. Search the full city database, keep guessing without a limit, or choose Give up to reveal the answer. Duplicate guesses do not increase the count. Next city resets the round and generates new clues; there is no score or timer.

`dist/compass-model.js` owns city selection, clue sampling, diagram layout and round transitions. `node --test tests/*.test.mjs` checks pool breadth, distinct references, outward bearings, geographic variety, label spacing, unlimited guesses and completion. Browser checks cover search, duplicate guesses, reveal, correct answers, round resets and mobile layout. GeoNames data and attribution follow the city search license above. Optional WebMCP tools expose the same read/search/guess/give-up/next actions; native WebMCP validation was unavailable in the local test browser.

## City History

Open `history.html`, the fifth game. Guess a city from its timeline of political control: empires, kingdoms, republics, colonial administrations, occupations and periods of autonomy. The collection contains **100 cities and 750 periods**: 40 European cities and 60 elsewhere, with expanded coverage of colonial ports and contested cities in Asia and the Americas. Each round starts with the earliest period. Reveal next adds one owner at a time in chronological order; players can guess after any reveal, or reveal again without guessing. Each new wrong guess reveals the next period automatically; duplicates do not advance the timeline. Reveals do not consume guesses or affect points. The full timeline appears after a correct answer or Give up. Use the worldwide city search, including curated historical aliases such as Danzig, Königsberg, Ragusa and Pondicherry. Guesses are unlimited, duplicates do not increase the count, and Give up reveals the answer. Completed rounds offer a collapsed Notes & sources section with historical context and source links. The shuffled deck does not repeat until exhausted, including across the deck boundary. There is no score, timer, daily schedule or external history API at runtime.

`dist/history-data.json` contains manually researched factual summaries, checked through 26 October 2026, with sources for each city. These are **selected major periods**, not exhaustive lists of every ruler or military presence. A timeline may start in the medieval or modern era even when the city is older. Labels distinguish occupation, sovereignty, suzerainty and local autonomy where relevant; notes explain condensed intervals, contested dates and the historic area followed. A date shared by two rows marks a transition during that year. `c.` marks approximate dates. Same-year transfers, such as New Orleans' twenty days of French administration in 1803, can have a single-year row. Modern-state rows may span changes in domestic government.

Clues use short state or ruler labels; suzerainty distinctions remain in the clues, while longer qualifications appear under Notes & sources after completion. City names in political titles are generalized to avoid revealing the answer (for example, an independent maritime republic). The actual name and sources appear only after completion. Source articles, including Wikipedia, remain subject to their own licenses; the game's short factual timelines are newly written summaries, not copied article prose. GeoNames supplies city identities, search aliases and modern country labels under CC BY 4.0 as described above. The city database's names do not assert historical sovereignty.

`dist/history-model.js` handles chronology formatting, guesses and the shuffled deck. Run `node --test tests/*.test.mjs` for identity and alias checks, chronological continuity, source URLs, clue-name leaks, unique timelines, answer concealment, duplicate handling and deck exhaustion. Feature-detected WebMCP tools expose read/reveal/search/guess/give-up/next through the same actions; native WebMCP verification was unavailable in the local test browser.

## Battle Leaders

Open `battles.html`, the sixth game. The initial collection has **45 battles** spanning antiquity to the twentieth century, with **531 commander entries** across the two sides. Each round shows the battle name, date and belligerents. Click a side: the winning side earns 1 point. Then type one commander from either side: a winning-side commander earns 3 points, a losing-side commander earns 1, and an unrecognized name earns 0. Commander points are independent of the winner prediction, for a maximum of 4 per round. There is one commander attempt or Skip; empty and ambiguous names do not consume it. Score accumulates for the current page session and resets on reload. The shuffled deck visits every battle before repeating and avoids repeating at its boundary. Displayed sides are randomized each round.

`dist/battles-data.json` contains researched belligerents, clear infobox outcomes, and all named commanders/leaders in the linked Wikipedia battle infoboxes, checked on 26 October 2026. The roster can include high command, political leaders and support roles when the infobox does; material qualifications appear in Notes & sources. Battles with disputed or split results are excluded from this first collection. Infobox side placement determines commander scoring. Commander matching ignores case, accents and punctuation, and accepts curated common surnames, titles, transliterations and alternate names. It does not use fuzzy substring matching or offer an answer list before the attempt. Both full commander rosters appear as ordinary visible lists after Skip or a submitted attempt and are brought into view. They have no collapse controls. The matched name, points, notes and source links are also revealed. Factual fields are transcribed and condensed rather than copying article prose; no live Wikipedia API is required to play.

`dist/battles-model.js` owns scoring, stages, side order, matching and deck transitions. `node --test tests/*.test.mjs` checks all winner/commander scoring combinations, duplicate submission protection, invalid inputs, answer concealment, skip, deck exhaustion, source fields and every name/alias. Optional WebMCP tools expose read/pick/name/skip/next through the same actions; native WebMCP verification is unavailable in the local browser.

## Life Map

Open `figures.html`, the seventh game. Guess one of **200 deceased historical figures** from their birth and death years and places, shown as two labelled map pins. The collection retains the original 60 figures and adds 140 across more countries, including ancient and medieval figures as well as people from Africa, Latin America, the Caribbean and Oceania. Three different wrong guesses automatically reveal the name; a correct guess reveals it immediately. Reveal can also end a round early. Repeated guesses, including alternate names for the same known figure, do not consume attempts. Free-text answers accept curated surnames, transliterations and alternate names, ignoring case, accents and punctuation. Empty and ambiguous names do not consume attempts. There is no score or timer. The shuffled deck visits every figure before repeating and avoids repeating the figure across the deck boundary.

The map supports pan/zoom and Fit places. Blue marks birth; orange marks death. When both coordinates coincide, a shared pin displays separate birth and death labels. Years marked `c.` are approximate. Pins describe modern settlements or approximate localities, not guaranteed exact buildings; contemporary place names and borders help locate historical places. `dist/figures-data.json` contains independently checked life events and source links, checked on 27 October 2026. Notes explain approximate dates, disputed rural sites, historical names and differences between death and burial locations. Identity, notes and source links are shown after completion. All earlier cities and games remain in their original pools.

MapLibre uses the bundled public-domain Natural Earth country outlines in `dist/world-countries.geojson`, with optional standard OpenStreetMap raster detail requested only for the visible viewport. The outline basemap and labelled pins remain when detailed tiles fail; Retry map detail retries that layer. Tile requests use normal browser identification, referrer and HTTP caching; no tile prefetch or offline tile archive is included. Attribution is visible below the map. Natural Earth provenance is in `dist/world-countries-LICENSE.txt`.

`dist/figures-model.js` handles names, year formatting, map bounds, guess limits and deck transitions. `node --test tests/*.test.mjs` checks all identities and aliases, coordinates, distinct life clues, approximate years, three-miss reveal, correct answers on every attempt, duplicates, early reveal, deck boundaries, co-located events and antimeridian framing. Optional WebMCP actions expose read/guess/reveal/next through the same game state. Script and stylesheet URLs are versioned so preview reloads pick up rendering changes.

## Cricket Grounds

Open `cricket.html`, the eighth game. Type the cricket ground's name from a label-free ground diagram. The deck contains **27 distinct grounds** from XrysD's Wikimedia Commons uploads: 18 in England/Wales, four in Australia, three in India, one in New Zealand and one in Rwanda. Names, familiar abbreviations (MCG, SCG, WACA), former names and selected sponsor names are accepted. Matching ignores case, accents, punctuation, dotted initials and an optional leading “The”; it does not accept arbitrary substrings. Guesses are unlimited, duplicate names/aliases do not increase the count, and Give up reveals the answer. Correct guesses and Give up show the location, original diagram link and contributor credits. Next ground clears the round. There is no score or timer, and the shuffled deck visits every ground before repeating, including protection against a repeat across the deck boundary. No new runtime API is needed.

All 27 SVGs are bundled in `dist/cricket-outlines/`. The outlines retain the original geometry and colours of the stands, ground and pitch, while the entire Labels layer (including lettering converted to vector paths) is removed. Generic attribution replaces embedded descriptions, and neutral filenames/alt text avoid naming the answer. These are diagrams as drawn in the original uploads; they need not reflect current redevelopment. `dist/cricket-data.json` stores accepted names, original file URLs, contributor credits and license provenance, checked on 5 November 2026. `dist/cricket-credits.txt` records attribution and changes for every image. Original and adapted artwork is **CC BY-SA 4.0**, by XrysD and the credited Commons contributors; this artwork license does not relicense unrelated site code.

To regenerate from downloaded originals, run `python3 scripts/build-cricket-grounds.py /path/to/cricket-research/grounds.json` with a manifest containing each ground's sourcePath, names, aliases, place, source/asset URLs, author, contributors and license metadata. The importer verifies label-layer removal and rejects active/external SVG content. `node --test tests/*.test.mjs` checks all accepted names, sourced assets, label removal, unlimited and duplicate guesses, give-up/correct transitions and deck exhaustion.

## Coat of Arms

Open `arms.html`, the ninth game. Name the current country from its national coat of arms, emblem or state seal. The collection contains **192 countries** from the UN member/observer-state set, with one selected symbol per country. Türkiye, Libya and Lebanon are omitted because the source gallery has no suitable official national arms entry. France's familiar diplomatic emblem and Japan's Imperial Seal are included with qualifications after reveal. Afghanistan uses the emblem of the de facto government; Syria and Trinidad and Tobago use their 2025 designs. Notes identify relevant variations. All 192 symbols have been reviewed; readable country-name lettering in Latin script is removed directly from 44 SVGs; ribbons, frames and heraldic details remain. Mottos stay except for a country name embedded within a motto. Non-Latin inscriptions remain.

Search the country list and select an answer with a click, or arrow keys and Enter, then choose Guess. Searches include common English names, selected alternative names, abbreviations and spelling forms. Invalid or incomplete searches do not consume guesses. Guesses are unlimited; case, accents and punctuation are ignored. Searching “Congo” or “Korea” offers the distinct countries to choose from. Guesses match whole accepted names, so Niger and Nigeria remain distinct, and England is not a UK alias. Duplicate aliases do not add another attempt. A correct answer or Give up reveals the country, source artwork link, author and licence. Next country resets the round, and the shuffled deck visits every country before repeating. There is no score, timer, daily schedule or runtime dependency on Wikimedia.

SVG artwork is bundled in `dist/arms-images/`, under neutral filenames with non-revealing alternative text. Country-name removals are recorded as adaptations per image, and image URLs are versioned to refresh cached originals. Checksums preserve both the source original and the quiz version. Each image retains its own licence and attribution, including public-domain, CC BY, CC BY-SA, CC0 and attribution-only files. The linked `dist/arms-credits.html` lists every source, creator and licence; it is always accessible from the game. `dist/arms-data.json` preserves the source file names, original download URLs, licence metadata and SHA-256 checksums, checked on 5 November 2026. Source selection: [Wikipedia's gallery of national coats of arms](https://en.wikipedia.org/wiki/Gallery_of_coats_of_arms_of_sovereign_states), with artwork and file licences from Wikimedia Commons. This dataset defines a game pool, rather than a statement about diplomatic recognition.

To regenerate from researched/downloaded originals, run `python3 scripts/build-arms-game.py /path/to/arms-research/manifest.json /path/to/arms-redacted`. The review is retained in `scripts/arms-redaction-review.json`. The importer requires a complete review of all 192 images when applying edits, verifies SVG dependencies and unchanged image bounds, adds answer aliases, and generates the public dataset and credits with adaptation notes. It rejects added rectangle or image overlays. Without the optional edits directory it can rebuild the original-source version. Run `node --test tests/*.test.mjs` for country identities and aliases, licences and source URLs, local artwork checksums, ambiguous/duplicate answers, unlimited guesses, answer concealment, completion and deck exhaustion.
